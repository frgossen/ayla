# Measured M192 routes on B200

The routing table selects M192/N64, CTA group 2 for three exact FP16 MM
shapes. M192 composes native M128 and M64 updates using shared operands
and one packed TMEM arena. Existing schedules can also select
`output_m_tile=192` explicitly.

| Shape M×N×K | cuBLAS reference (µs) | M192 (µs) | Speedup | Gain vs matched M128 on two GPUs |
| --- | ---: | ---: | ---: | ---: |
| 1000×1280×32 | 5.000 | 4.512 | 1.108× | 9.0–12.9% |
| 1000×1280×96 | 5.540 | 5.000 | 1.108× | 8.2–8.3% |
| 1000×1536×64 | 5.424 | 4.736 | 1.145× | 11.6–12.6% |

These shapes previously used cuBLAS fallback. Timings use three
rotating-order trials of 15 rounds, preallocated output and inference-v2
with a 256 MiB flush. References for fallback shapes pool two equivalent
cuBLAS rows. Every accepted kernel passes three changed-input CUDA graph
replays against FP32 accumulation, with poisoned output and guard regions.
The winning schedules also passed memcheck and racecheck. Reported times
are confirmation measurements; controls are separate runs on two GPUs.

A separate check of the isolated commit over `e3e3c87`, using the tracked
router benchmark on GPU 6, measured 4.872/5.208, 5.072/5.464 and
4.992/5.496 µs (M192/cuBLAS, in table order): 1.069×, 1.077× and 1.101×.
All three routes still beat cuBLAS with the other uncommitted compiler
changes excluded. The isolated checkout passed 102 CPU tests (15 GPU
cases skipped), all 39 composition/route tests on B200, and the route
replays under both memcheck and racecheck with zero errors or hazards.

For M1000/N1280, M192 needs 60 CTA pairs while M128 needs 80. For N1536,
those counts are 72 and 96. CUDA's `cuOccupancyMaxActiveClusters` confirms
74 active pairs for the M192, M128 and M64 images on the first and third
shapes. M192 therefore crosses from two waves to one despite doing an
additional M64 update. The ideal compute-adjusted gain is 4/3.

The corpus scan covered all 758 canonical FP16 MM shapes. It screened
227 candidates and attempted 2,377 configurations; 2,014 passed compilation
and correctness. Twenty-nine finalists received confirmation runs and
18 received matched M128/M64 controls. Multicast did not win among the
confirmed finalists. Other gains were too small or were also achievable
with M128, so this change adds only the three consistent paired winners.

The selector returns a fresh configuration for an exact shape and dtype:

```python
from ayla.gemm_collection.blackwell_tcgen05 import (
    blackwell_tcgen05_gemm_module,
    select_blackwell_gemm_schedule,
)

config = select_blackwell_gemm_schedule(1000, 1280, 32, dtype="f16")
module = blackwell_tcgen05_gemm_module(
    m=1000, n=1280, k=32, dtype="f16", **config,
)
```

M192 supports native, cyclic and rolled K schedules, single or paired CTAs,
and multicast. It requires at most 256 output columns per tile; grouped
output tiles and persistent output rings are unsupported. Paired M192
requires one output slice and buffer, and enough registers for the whole
M64 writeback component. The routed schedules use N64 and register budget
64; exact K tiling and operand stages are recorded in the routing table.

Local research artifacts are retained under
`.benchmarks/b200_m192_wave_sweep_20261119/`: summary tables, candidate wave
models, exact configurations, PTX, cubins, SASS, occupancy queries, raw
trials, validation and sanitizer logs. These artifacts are not versioned.
